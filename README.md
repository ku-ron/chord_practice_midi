# コード弾き練習 MIDI Ver.

電子ピアノをつなぎ、五度圏のホイールに出たコードを実際に鍵盤で弾いていく練習ツールです。押した音をMIDIで受け取って正誤を判定し、**正しく押せた区画には色が残ります**。ブラウザだけで動きます。

**→ 練習アプリ　https://ku-ron.github.io/chord_practice_midi/**

**→ MIDIモニタ　https://ku-ron.github.io/chord_practice_midi/monitor.html**

姉妹プロジェクト [コード進行 12キー練習ホイール](https://github.com/ku-ron/chord_practice)（[公開版](https://ku-ron.github.io/chord_practice/)）にMIDI入力を足したものです。ホイールが「どのコードを弾くか見せる」までなのに対し、こちらは「ちゃんと弾けたか」まで見ます。ホイール・プリセット・進行の編集・調の巡り方・テンポ再生は、そのまま引き継いでいます。

## ⚠ iPad・iPhone では専用ブラウザが要ります

**Safari は Web MIDI API に対応していません。** macOS版・iOS/iPadOS版とも未対応で、[WebKitのバグ票](https://bugs.webkit.org/show_bug.cgi?id=107250)は2013年から開いたままです。iOSはすべてのブラウザがWebKitを使うため、iPad版のChromeやFirefoxを入れても同じです。

そのため iPad・iPhone では **[MIDIWeb Browser](https://apps.apple.com/us/app/midiweb-browser/id6757226617)**（無料）でこのページを開いてください。Bluetooth MIDI のペアリングもこのアプリの中から行います。

| 環境 | どうするか |
|---|---|
| Mac / Windows | **Chrome、Edge、Firefox 108+** でURLを開くだけ |
| Android（未検証） | **Chrome、Samsung Internet** で開けば動くはず（下記） |
| iPad / iPhone | **MIDIWeb Browser** でURLを開く |
| Mac版Safari | MIDIは動きません（ホイールとテンポ再生は動きます） |
| Firefox for Android | **非対応**（デスクトップ版とは違い Web MIDI がありません） |

**iPad + MIDIWeb Browser + Roland DP603（Bluetooth MIDI）** と **Mac版Chrome** の2経路だけを実機で確認しています。それ以外は未検証です。

## つなぎ方

```
電子ピアノ ──(Bluetooth MIDI または USB)──→ 端末     判定用のデータ
電子ピアノ ──(ヘッドホン・内蔵スピーカー)──→ 耳      弾いた音
```

**弾いた音は電子ピアノ自身に鳴らさせてください。** アプリが鳴らすのはテンポモードのクリック音だけです。

Bluetooth **オーディオ**は使わないでください。名前は似ていますが Bluetooth MIDI とはまったく別の技術で、遅延が150〜250msあります（BLE MIDI は3〜6ms）。クリック音がそれだけ遅れると、合わせて弾くことが不可能になります。設定アプリ側でBluetoothオーディオの接続を切っても、MIDIは切れません（管理場所が別です）。

電子ピアノをMIDIコントローラとして使うと、機種によっては**ローカルコントロールがOFFになり本体から音が出なくなります**。このツールはピアノ自身の音で弾くことが前提なので、ONのままにしてください。ピアノが突然無音になったらこれを疑ってください。

## 使い方

画面いちばん上の「MIDIに接続」を押すと、見えている入力デバイスをすべて監視します（つないだ機器名がその右に出ます）。あとは光っている区画（NOW）のコードを弾くだけです。

### 2つの進み方

| | |
|---|---|
| **弾いて進む** | 正しい音の集合がそろった瞬間に次の区画へ。時間制限もクリック音もありません |
| **テンポ** | 従来どおり拍で自動的に進みます。その拍のうちに正しく押せれば区画に色が残ります。**停止中とカウントイン中は判定しません**（いま弾くべき区画が出ていないため） |

テンポでは、**拍の頭より少し早く押さえてもかまいません。** 人は拍ちょうどには押さえないので、拍が変わった時点ですでに正しく押さえていれば、その直前の打鍵ぶんは拾います（既定300ms。設定で変えられます）。ずっと押しっぱなしのものは、弾いた行為ではないので拾いません。1回の打鍵が2つの区画に数えられることもありません。

切り替えはホイール下のボタンで。テンポ・拍数・再生ボタンは、テンポモードのときだけ出ます。

同じ行の**「同じ調で繰り返す」**を入れると、進行を1周してもキーが変わらず、同じ調のまま繰り返します。ひとつの調をじっくりさらいたいときに。入れているあいだは「次の調」の表示も消えます（行き先が無いので）。

テンポモードでは、**ホイールの右下でメトロノームの振り子が振れます。** クリック音は内蔵スピーカーだと聞き取りにくく、かといって上で書いたとおりBluetoothオーディオへは流せないので、目でも拍が取れるようにしてあります。

- 振り子は**1拍で片道**。コードの頭拍は**左**から始まります
- 下の点は**1コードあたりの拍数**だけ並び、**いまの拍まで塗りつぶされます**（1拍ずつ埋まっていく）
- **クリック音が鳴る瞬間に、その点が脈打ちます。** 1コード1拍だと点が1個しかなく、塗りつぶしだけでは拍が分からないためです
- カウントインの残り数は振り子の上に出ます

### 押せた区画に色が残る

正しく押せた区画は**緑**に変わり、そのまま残ります。12調ぶんのどこが押せて、どこが手つかずかが一目で分かります。右下に `押せた 10 / 36` と数も出ます。

**いま光っている区画も、すでに押せていれば緑で光ります**（まだなら金色）。同じところを繰り返しているのか、新しいところに来たのかが色で分かります。

印は「調」と「進行内の位置」で覚えているので、調の巡り方を変えても残ります。**進行の中身を変えると（プリセットの選択、コードの追加・削除・並べ替え、ルート／クオリティ／ベースの変更、長調⇄平行短調）位置の意味が変わるので、印は消えます。**

自分で消したいときは、**ホイールの右上の「リセット」**を押してください（編集パネルの「押せた印をリセット」も同じ働きです）。再生ボタンも同じところに置いてあります。下の行だと指が届きにくいためです。**リセットは押せた印だけでなく、進行の途中まで来ていた位置も最初（いちばん外側）へ戻します。**

### 全部できたら

12調ぶんが全部埋まったときの動きを選べます（ホイール下の「全部できたら」）。

| | |
|---|---|
| **ループ** | 何もせずそのまま続けます（既定） |
| **停止** | そこで止まります。テンポなら再生も止まり、「弾いて進む」なら進まなくなります。リセットを押すと再開します |
| **リセット** | 印を全部消して、そのまま続けます |

### 弾いている音

ホイールの下の細い鍵盤に、いま押している音が出ます。

- **青** — コードの構成音
- **赤** — 余分な音
- **金** — 最低音（要求どおりのとき）

鍵盤の下には、**いま押している音が名前で並びます**（`D4` `F4`）。コードに無い音は赤くなります。

**「鍵盤ヒント」**を押すと、**そのコードの構成音が鍵盤に印で出ます**。オクターブ違いも全部出るので、どこを押してもよいかが見えます。

- **青い丸** — 必須の音
- **青い輪** — 任意の音（テンションの5度）
- **金の丸** — 最低音として要求される音

押している音は鍵ぜんぶが染まるので、印とは大きさで見分けがつきます。

弾くべきコードはホイールに出ているので、コード名の大きな表示は置いていません。構成音の音名も既定では出しません（記号から音を導くのが練習の中身なので）。鍵盤の右下の**「音名ヒント」**を押すと、その行が**構成音の並び**に変わり、押せている音だけ色が変わります（任意の音は破線、最低音として要求される音には枠が付きます）。**コードに無い音を押しているときだけ、右に「余分」として足されます** — 構成音の色がそのまま「押せているか」を示すので、押している音をもう一列出す必要がないためです。

### 赤くならない場面

余分な音を**新しく押した**ときだけ赤くなります。次の3つでは咎めません。

- **前のコードを離している途中** — 1音ずつ離すと残りが一瞬「余分」に見えますが、間違いではありません
- **正解の直後に遅れて届いた指** — オクターブの重ねや押しムラ。既定300ms待ちます
- **和音を組み立てている途中の最低音** — 3度を先に押しただけで咎めるのは早すぎるので、必要な音がそろってから見ます

すでに赤いときは、余分な音が残っているかぎり離しても赤のままです。

## 判定の仕様

**押している音のピッチクラス集合が過不足なく一致していればOK。分数コードのときは加えて、指定したベース音が最低音であること。**

| | |
|---|---|
| 押す順番 | **見ない**（同時に押されている集合だけを見る） |
| 余分な音 | **不正解** |
| オクターブ違い・音の重複 | **自由**（同じ音を何オクターブ重ねてもよい） |
| 分数コードのベース | **最低音であることを要求** |
| 分数コードでないコードの最低音 | **選択式**（ルートを最低音に要求する／転回形を許す。既定は前者） |
| テンション（`7(9)` `m7(9)` `7(♭9,13)` など） | **5度の省略を許す**。それ以外の音は必須 |
| ダンパーペダル | **見ない**（ノートオフは通常どおり届くので集合は正しく保たれます） |

`F/G` の構成音は F A C で **G は構成音ではありません**が、指定されたベース音は必須かつ許容の集合に入るので、G を押さないと正解になりません。転回形（`C/E` のようにベースが構成音）は分岐なしに同じ式で扱えます。

最低音の判定だけはピッチクラスではなく実際のMIDIノート番号で見ています。ここでオクターブを潰すと「最低音であること」が判定できなくなるためです。

同じコードが続く場合（ブルースの折り返しなど）は、**弾き直すまで次に進みません。** 押したままオクターブを足しても、ピッチクラス集合が変わらないので正解が積み上がることはありません。

猶予は**間違いを咎めるときにだけ**使います。人は和音を完全に同時には押さないので、コードの移り変わりの途中で必ず誤った集合を通過するためです。**正解の判定には猶予を使いません**（足りない状態は「まだ途中」でしかなく、誤判定にならないので、そろった瞬間に正解にできます）。

## ホイールの読み方

中心に五度圏を置き、その外側に、いま弾くコードを扇形で並べたものです。

- **中心の輪** — 外側が長調、内側が平行短調
- **外側の輪** — 弾くコード。**外から内へ**弾き、いちばん内側が着地するコード
- **扇形** — 同じ扇の中にある調とコードが対応します
- **実線の輪郭＝現在の調／破線＝次の調**。区画の光る枠が「いま弾くコード」、破線の枠が「次に弾くコード」
- **中心の図形** — 巡回の経路。パターンごとに違う形になります。五度圏上の配置なので、**4度上は隣どうしを回るため正十二角形、半音上は7つ飛ばしなので星形**です（姉妹アプリのREADMEはこの対応が逆に書かれていますが、実際に描かれるのはこちらです）

たとえば `IV–V–I` を指定すると、Cの扇には外から F → G → C が、Gの扇には C → D → G が並びます。12の調に同じ進行が同時に見えている状態です。

進行は「調のトニックからの距離」として保持しているので、どの調でも異名同音が正しく綴られます。G♭ の Ⅳ は C♭ と出ます。

## 編集

**コード進行の選択（プリセット71種）は、五度圏のすぐ下に常時出しています。** 練習中にいちばん触るものなので、開閉の奥に置きません。その下の「編集を開く」から、姉妹アプリと同じ細かい編集ができます。

- **プリセット**（常時表示） — 71種類を7つのタブに（三和音／四和音／定番／中級／上級／短調／テンション）。各タブの末尾に分数コードを使った型
- **進行** — コードの追加・削除・並べ替え。コード名でも度数でも指定でき、分数コードにもできます
- **コードの種類** — 基本15種（三和音・四和音・`aug7`・`add9` など）と、**テンション18種**。テンションは`Cm7(9)`のように、**セブンスまでのコードに括弧で足す表記**です（`7(9)` `7(♭9)` `7(♯9)` `7(♯11)` `7(13)` `7(♭13)` `7(9,13)` `7(♭9,13)` `7(♭9,♭13)` `7(♯9,♭13)` `7(9,♯11)` `maj7(9)` `maj7(♯11)` `m7(9)` `m7(11)` `m7(9,11)` `m7♭5(11)` `mM7(9)`）。変化記号は数字の前に置きます（`♭9`。`9♭`とは書きません）
- **調の巡り方** — 4度上、5度上、短2度・長2度・短3度・長3度の上下、ランダム。途中で輪が閉じるパターンでは、未通過の調へずらして次の輪に入ります
- **判定（MIDI）** — 最低音のきまり、音名ヒント、鍵盤ヒント、押せた印をリセット、猶予・正解後の待ち・拍より早く押さえてよい幅（全部できたときの動きはホイール下）
- **拍とカウント** — テンポモード用。1コードあたり1／2／4拍、カウントイン なし／4拍／8拍
- **表示** — テーマ（ダーク／ライト）、コード表記（標準／ジャズ）、度数、ダブル♯♭の簡略化、経路

### キーボード

| キー | 動作 |
|---|---|
| `Space` | テンポの再生／停止 |
| `→` `←` | 次／前の調（画面では五度圏の区画をタップして移ります） |

## 動作環境

- MIDIの権限を求めるので、**https か localhost** で開く必要があります
- 入力デバイスはすべて監視します。仮想ポートやネットワークセッションが同じ信号をミラーしていても、押している音を集合で持っているため重複は自然に吸収されます
- **設定と進行はこの端末に保存され、次に開いたときも残ります。** 全画面モードには再読み込みボタンが無く、開き直すたびに選び直すのは負担が大きいためです。押せた印といまの位置は残しません（毎回まっさらから始まります）
- テンポモードの音は Web Audio API を使います。Safari は他のアプリに音声を取られると標準にない `interrupted` 状態に入りますが、そこから戻れるようにしてあります
- iPadやiPhoneで**ホーム画面に追加**すると、アイコンから全画面で開きます

## MIDIモニタ

`monitor.html` は、受信したMIDIをそのまま画面に流すだけのツールです。**→ https://ku-ron.github.io/chord_practice_midi/monitor.html**

機材が何を送ってくるか調べるときに使います。生バイトと解読を並べたログのほか、次の項目を自動で集計します。

- **ノートオフの表現** — 「ノートオフ(`0x80`)」ではなく「ベロシティ0のノートオン(`0x90`)」を送る機種があります。どちらが来ているか
- **ダンパー(CC64)** — 0/127の2値か、0〜127の連続値（ハーフペダル対応機）か
- **チャンネル**、ベロシティ範囲、ノート番号の範囲、受信メッセージ種別

機材がなくても、テスト入力ボタンから偽のMIDIを実機と同じ処理経路に流せます。

## 構成

`index.html`（練習アプリ）と `monitor.html`（モニタ）の2ファイルだけです。ビルドは不要で、外部から読むのは Google Fonts のみ。

### 音名は五度圏上の整数で持つ

姉妹アプリから引き継いだ中核です。音名を半音数ではなく**五度圏上の距離**で保持すると、異名同音が調ごとに正しく綴られます。F♯調のⅦは `E♯`、G♭調のⅣは `C♭` と出ます。

```js
const pcOf = n => mod(n * 7, 12);   // 五度圏インデックス → ピッチクラス(0-11)
```

`pcOf` がMIDIとの接続点です。判定はピッチクラスで行い、表示は綴りのまま出せます。

### 構成音も五度圏で持つ

コードの構成音を半音（`m7`→`[0,3,7,10]`）で持つと、判定はできても綴りが失われます。五度圏上の距離で持てば両方が出ます。

```js
//  0=R  4=M3  -3=m3  1=P5  -6=♭5  8=♯5  -1=P4  3=6th/13th  -2=m7  5=M7  2=9th
'm7'  : {req:[0,-3,1,-2]},
'9'   : {req:[0,4,-2,2], opt:[1]},   // テンションでは5度を任意にする
```

`req` が必須、`opt` があってもなくてもよい音、それ以外は禁止です。`dim7` の第7音は厳密には重減7度（C dim7 なら B𝄫）ですが、読みやすさを優先して `+3`（=A）で綴っています。

### 描画は2段に分ける

ホイールはSVGを毎回組み直すので重く、ノートを押すたびに走らせると速く弾いたときに詰まります。鍵盤と判定の一行だけを更新する軽い経路と分けてあり、ホイールの描き直しは区画が移ったときと赤くなったときだけです。

## 設計上の覚え書き

- **なぜコード名を大きく出さないのか** — ホイールの光っている区画がそのまま「いま弾くコード」だからです。同じものを2か所に出すと視線が散ります
- **なぜ答え（構成音の音名）を隠すのか** — コード記号から構成音を導くことが練習の中身だからです。音名を常に出すと、画面を読んで押すだけの作業になります
- **なぜ押せた印を進行の編集で消すのか** — 印は「調と進行内の位置」で覚えています。進行の中身が変われば位置の意味が変わるので、残すと嘘になります。調の巡り方を変えるだけなら位置の意味は変わらないので残します
- **なぜ専用アプリ1本への依存が軽いのか** — MIDIWeb Browser は入れ物にすぎず、中身はただのWebページです。将来使えなくなってもCapacitorで包み直せばよく、それは包装の作り替えであって書き直しではありません。判定ロジックがWeb標準の上に乗っている限り、乗り換えコストは低いままです
