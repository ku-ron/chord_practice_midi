# コード弾き練習（MIDI入力）

電子ピアノをつなぎ、画面に出たコードの構成音を実際に鍵盤で弾いていく練習ツールです。押した音をMIDIで受け取って正誤を判定します。ブラウザだけで動きます。

**→ 練習アプリ　https://ku-ron.github.io/chord_practice_midi/**

**→ MIDIモニタ　https://ku-ron.github.io/chord_practice_midi/monitor.html**

姉妹プロジェクト [コード進行 12キー練習ホイール](https://github.com/ku-ron/chord_practice)（[公開版](https://ku-ron.github.io/chord_practice/)）から派生しています。ホイールが「どのコードを弾くか見せる」までなのに対し、こちらは「ちゃんと弾けたか」まで見ます。

---

## ⚠ iPad・iPhone では専用ブラウザが要ります

**Safari は Web MIDI API に対応していません。** macOS版・iOS/iPadOS版とも未対応で、[WebKitのバグ票](https://bugs.webkit.org/show_bug.cgi?id=107250)は2013年から開いたままです。iOSはすべてのブラウザがWebKitを使うため、iPad版のChromeやFirefoxを入れても同じです。

そのため iPad・iPhone では **[MIDIWeb Browser](https://apps.apple.com/us/app/midiweb-browser/id6757226617)**（無料）でこのページを開いてください。Bluetooth MIDI のペアリングもこのアプリの中から行います。

| 環境 | どうするか |
|---|---|
| Mac / Windows / Android | **Chrome、Firefox 108+、Edge** でURLを開くだけ |
| iPad / iPhone | **MIDIWeb Browser** でURLを開く |
| Mac版Safari | 動きません（Web MIDI 非対応） |

## つなぎ方

```
電子ピアノ ──(Bluetooth MIDI または USB)──→ 端末     判定用のデータ
電子ピアノ ──(ヘッドホン・内蔵スピーカー)──→ 耳      弾いた音
```

**弾いた音は電子ピアノ自身に鳴らさせてください。** アプリは音を出しません。

Bluetooth **オーディオ**は使わないでください。名前は似ていますが Bluetooth MIDI とはまったく別の技術で、遅延が150〜250msあります（BLE MIDI は3〜6ms）。iPadから音を返すと、合わせて弾くことが不可能になります。設定アプリ側でBluetoothオーディオの接続を切っても、MIDIは切れません（管理場所が別です）。

電子ピアノをMIDIコントローラとして使うと、機種によっては**ローカルコントロールがOFFになり本体から音が出なくなります**。このツールはピアノ自身の音で弾くことが前提なので、ONのままにしてください。ピアノが突然無音になったらこれを疑ってください。

## 使い方

「MIDIに接続」を押すと、見えている入力デバイスをすべて監視します。あとはコードが出るので弾くだけです。

- **正しい音の集合がそろった瞬間に次へ進みます。** 時間制限もクリック音もありません
- 進行を1周すると**キーが変わります**
- 押している音は鍵盤とチップに出ます。**構成音の答えは出ません** — 記号から音を導くのが練習の中身なので、既定では隠してあります。「音名ヒント」でいつでも出せます
- 間違えると、余分な音が**赤**になります。最低音が違うときはその旨が出ます
- **前のコードを離している途中では赤くなりません。** 1音ずつ離すと残りの音は一瞬「余分」に見えますが、それは間違いではないので咎めません（赤くするのは新しく鍵盤を押したときだけ）。すでに赤いときは、余分な音が残っているかぎり離しても赤のままです
- **和音を組み立てている途中でも、最低音は咎めません。** 3度を先に押しただけで「最低音が違う」と言われても仕方がないので、必要な音がそろってから見ます（余分な音はいつでも間違いです）

### 判定の仕様

**押している音のピッチクラス集合が過不足なく一致していればOK。分数コードのときは加えて、指定したベース音が最低音であること。**

| | |
|---|---|
| 押す順番 | **見ない**（同時に押されている集合だけを見る） |
| 余分な音 | **不正解** |
| オクターブ違い・音の重複 | **自由**（同じ音を何オクターブ重ねてもよい） |
| 分数コードのベース | **最低音であることを要求** |
| 分数コードでないコードの最低音 | **選択式**（ルートを最低音に要求する／転回形を許す） |
| テンション（`9` `m9` `13` `add9`） | **5度の省略を許す**。それ以外の音は必須 |
| ダンパーペダル | **見ない**（ノートオフは通常どおり届くので集合は正しく保たれます） |

`F/G` の構成音は F A C で **G は構成音ではありません**が、指定されたベース音は必須かつ許容の集合に入るので、G を押さないと正解になりません。転回形（`C/E` のようにベースが構成音）は分岐なしに同じ式で扱えます。

最低音の判定だけはピッチクラスではなく実際のMIDIノート番号で見ています。ここでオクターブを潰すと「最低音であること」が判定できなくなるためです。

### 設定

「練習の設定」から。

- **コード進行** — プリセット60種を6つのタブに分けてあります（三和音／四和音／定番／中級／上級／短調）。ジャズの定番では「枯葉」のA節が中級に入っています。各タブの末尾には分数コードを使った型があります（カノンの下行ベース、半音で下りるベース、`IIm7/V` など）
- **キーの進み方** — 固定／4度上／5度上／半音上／全音上／短3度下／ランダム
- **最低音のきまり** — 分数コードでないコードで、ルートを最低音に要求するか、転回形を許すか（既定は**ルートを最低音に**）
- **表示** — コード表記（標準／ジャズ）、度数の表示
- **判定** — ミスを赤くするまでの猶予（既定60ms）、正解のあと判定を再開するまで（既定300ms）

分数コード（オンコード）は、この設定にかかわらず**指定したベース音が最低音であること**を常に要求します。選べるのは分数コードでないコードの扱いだけです。

猶予は**間違いを咎めるときにだけ**使います。人は和音を完全に同時には押さないので、コードの移り変わりの途中で必ず誤った集合を通過するためです。**正解の判定には猶予を使いません**（足りない状態は「まだ途中」でしかなく、誤判定にならないので、そろった瞬間に正解にできます）。

正解を「そろった瞬間」にする代償として、**その直後に遅れて届いた指**（オクターブの重ね、和音の押しムラ）が、次のコードに対する余分な音に見えてしまいます。「正解のあと判定を再開するまで」は、この分を待つ時間です。赤が出やすければ増やしてください。ここを長くしても正解の判定は遅くなりません。

## MIDIモニタ

`monitor.html` は、受信したMIDIをそのまま画面に流すだけのツールです。**→ https://ku-ron.github.io/chord_practice_midi/monitor.html**

機材が何を送ってくるか調べるときに使います。生バイトと解読を並べたログのほか、次の項目を自動で集計します。

- **ノートオフの表現** — 「ノートオフ(`0x80`)」ではなく「ベロシティ0のノートオン(`0x90`)」を送る機種があります。どちらが来ているか
- **ダンパー(CC64)** — 0/127の2値か、0〜127の連続値（ハーフペダル対応機）か
- **チャンネル**、ベロシティ範囲、ノート番号の範囲、受信メッセージ種別

機材がなくても、テスト入力ボタンから偽のMIDIを実機と同じ処理経路に流せます。

## 動作環境

- MIDIの権限を求めるので、**https か localhost** で開く必要があります
- 入力デバイスはすべて監視します。仮想ポートやネットワークセッションが同じ信号をミラーしていても、押している音を集合で持っているため重複は自然に吸収されます
- 音は一切鳴らしません。Web Audio を使っていないので、バックグラウンドに回して音が止まる類の問題は起きません
- ホーム画面に追加すると全画面で開きます
- 設定はページを開き直すとリセットされます

## 構成

`index.html`（練習アプリ）と `monitor.html`（モニタ）の2ファイルだけです。ビルドも外部依存もありません。

### 音名は五度圏上の整数で持つ

ホイール版から引き継いだ中核です。音名を半音数ではなく**五度圏上の距離**で保持すると、異名同音が調ごとに正しく綴られます。F♯調のⅦは `E♯`、G♭調のⅣは `C♭` と出ます。

```js
const pcOf = n => mod(n * 7, 12);   // 五度圏インデックス → ピッチクラス(0-11)
```

`pcOf` がMIDIとの接続点です。判定はピッチクラスで行い、表示は綴りのまま出せます。

### 構成音も五度圏で持つ

コードの構成音を半音（`m7`→`[0,3,7,10]`）で持つと、判定はできても綴りが失われます。五度圏上の距離で持てば両方が出ます。

```js
//  0=R  4=M3  -3=m3  1=P5  -6=♭5  8=♯5  -1=P4  3=6th/13th  -2=m7  5=M7  2=9th
'm7'  : {req:[0,-3,1,-2]},
'9'   : {req:[0,4,-2,2], opt:[1]},   // テンションでは5度を任意にする
```

`req` が必須、`opt` があってもなくてもよい音、それ以外は禁止です。`dim7` の第7音は厳密には重減7度（C dim7 なら B𝄫）ですが、読みやすさを優先して `+3`（=A）で綴っています。

### 最低音だけはノート番号で見る

ベースの判定でオクターブを潰すと「最低音であること」が判定できません。`Math.min(...heldNotes)` で実際のMIDIノート番号を取り、そのピッチクラスを比べています。

## 設計上の覚え書き

- **なぜ答えを隠すのか** — コード記号から構成音を導くことが練習の中身だからです。音名を常に出すと、画面を読んで押すだけの作業になります。「音名ヒント」で必要なときだけ出せます
- **なぜ時間で進めないのか** — クリック音を鳴らすとBluetoothオーディオの遅延問題に踏み込みます。自分のペースで進む形なら、アプリが音を出す必要がまったくなくなります。テンポで進むモードは後から足せます
- **なぜ専用アプリ1本に依存して平気なのか** — MIDIWeb Browser は入れ物にすぎず、中身はただのWebページです。将来使えなくなってもCapacitorで包み直せばよく、それは包装の作り替えであって書き直しではありません。判定ロジックがWeb標準の上に乗っている限り、乗り換えコストは低いままです
